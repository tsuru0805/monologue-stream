# monologue-stream

[English](README.en.md)

这个仓库做一件事：**让模型把"给人看的思考"亲笔写在回复开头**，再用一个单文件、零依赖的流式过滤器把这段独白从流式输出里拆出来，边生成边送进你应用的"思考链"UI。

它来自一个真实系统的真实病。我们的陪伴系统 tilldusk 里，思考链是体验的核心一环——她想看见他在想什么。2026 年 7 月我们查实：前端显示的"他的思考"根本不是他写的，那是 API 侧**另一个模型**压出来的摘要，他的人设和文风在里面荡然无存，而且没有任何参数能拿回原文。于是我们把思考搬进了正文——让他在每轮回复的开头亲笔写一段独白，网关流式拆分，前端零改。两周后，7 月下旬那波思考显示大收紧席卷各渠道，我们这条思考链一个字没少。

现在把这套机器抽出来开源。各模型思考显示的现状见下方速查表；如果你也在做"想让用户看见 AI 在想什么"的应用，这条路可以直接走。

```
提供商 thinking 通道(摘要/或不显示) ──────────▶ 随它去(那不是你要的)
正文卷首 [monologue] 块            ──filter──▶ 思考链通道(模型亲笔,吃你的人设)
其余正文                           ──filter──▶ 正文通道
```

## 各模型现状速查

按[官方文档](https://platform.claude.com/docs/en/build-with-claude/thinking)（2026-08 快照）：

| 模型 | thinking 默认开吗 | 开着的前提下，默认给你看什么 |
|---|---|---|
| Claude 5 家族（Opus 5 / Sonnet 5 / Fable 5）\* | 常开，无需配置 | **什么都不给**：thinking 字段返回空的，流式连 `thinking_delta` 事件都不发（`display` 默认 `"omitted"`）。要摘要，传 `display: "summarized"` |
| Opus 4.8 / 4.7 | **默认关**，传 `thinking: {"type": "adaptive"}` 才开 | 开了也默认 `"omitted"` 什么都不给；要摘要，再传 `display: "summarized"` |
| Opus 4.6 / Sonnet 4.6 及更早\* | 默认关，同样要手动开 | **一段摘要，不是原文**（`display` 默认 `"summarized"`）。摘要由**另一个模型**处理（官方原话）；在我们的生产抽样里，人设与文风在摘要中荡然无存 |

\* Mythos 5 / Mythos Preview 同属 `"omitted"` 默认；Haiku 4.5 及更早世代按 `"summarized"` 默认。

对所有模型都成立的两条：**任何 `display` 设置都拿不到原始 CoT**（官方原话：no `display` setting returns the raw chain of thought）；thinking token 一律**全量计费**，不管你看不看得到。

端上的处境类似但不完全相同：claude.ai 和桌面端没有任何用户侧开关；Claude Code 有一个（`showThinkingSummaries` 设置 + Ctrl+O 查看）——但你能打开的同样只是摘要。2026 年中以来用户报告的怪象五花八门：思考块缩成一句话、只剩一个动词、"Thought process is unavailable"、整个消失（[社区整理](https://claudelog.com/faqs/why-cant-i-see-claude-thinking/)）；也有用户报告思考链**半句断头**——本该是"今天天气真好"，显示到"今天天"就停，直接出正文（这一形态未见于上述整理，官方也没有针对它的说明）。不管你撞上哪种，根子是同一个：**你和模型真实思考之间隔着一条显示管线，而它不归你管。**

对陪伴、角色扮演、一切"想让用户看见 AI 在想什么"的应用，出路不在思考通道里，在正文里。

## 本仓解决什么、不解决什么

解决：

- ✅ **显示稳定性**——独白走正文通道，不经过任何 thinking 显示管线；无论断头、摘要化还是省略，思考链照常逐字到达。
- ✅ **声音归位**——思考链出自同一个模型亲笔、带人设、吃你的 system prompt 和文风。
- ✅ **流式直播**——独白边生成边进思考链，不是生成完再解析。
- ✅ **体验可设计**——思考的篇幅、语气、格式都由你的 prompt 决定。

不解决（诚实边界）：

- ❌ **不能恢复隐藏的原始 CoT**——独白是模型在上下文内写给人看的**可见自省**，不是内部推理原文。
- ❌ **不改变实际推理深度**——模型想多深由 thinking budget / effort 决定，与显示无关；"模型真的变笨了"那部分抱怨不在本仓射程内。
- ❌ **绕不过硬限制**——`max_tokens` 截断、流中断仍会发生（过滤器只保证截断时已写出的独白不丢，见下文特性）。

对陪伴/RP 场景来说，"亲笔的内心话"通常比"第三者的推理转述"更接近你真正想要的东西——但请清楚地知道你要的是哪一个。

## 特性

- **单文件、零依赖**——`monologue_filter.py`，复制进项目即可
- **流式**——独白边生成边进思考链，逐字直播，不是生成完再解析
- **标记撕裂安全**——`[monologue]` 被流式分块切成 `[mono` + `logue]` 也能正确识别（开标记走前缀匹配，闭标记走尾缀扣留）
- **逐字符 passthrough 保证**——不含独白的输入原样通过，旧数据、不写独白的轮次零影响
- **未闭合容忍**——模型忘写闭合标记时 `finish()` 把残段归还独白，内心话永不丢弃
- **只认卷首**——正文中途出现的标记一律当字面文本，不误解析
- **标记可配置**——默认 `[monologue]`/`[/monologue]`，可自定义（如 `<think>`/`</think>`；仅两个约束：不能为空串、开标记不能以空白开头）

## 快速开始

```python
from monologue_filter import MonologueFilter

f = MonologueFilter()
for delta in your_text_stream:          # 任意来源的流式文本增量
    text, mono, closed = f.feed(delta)
    if mono:
        emit_thinking(mono)             # → 你的思考链 UI 通道
    if text:
        emit_text(text)                 # → 你的正文通道
text, mono = f.finish()                 # 流尾收账——截断时的独白残段在这里
if mono:
    emit_thinking(mono)
if text:
    emit_text(text)
```

配上一段 system prompt（见下文[Prompt 写法](#prompt-写法)），就完成了。

## 三种集成方式

### 1. 直连 API（流式）

完整过滤器接入，见 [examples/anthropic_api_streaming.py](examples/anthropic_api_streaming.py)。要点：把 API 的 thinking 事件另存或忽略（若有——那是摘要，或干脆为空），把 text delta 过一遍过滤器再分发。前端如果已有"思考链"组件，事件契约不用改——内容换血即可。

### 2. Claude Code CLI（`claude -p` stream-json）/ Agent SDK

后端不碰原始 API、走 Claude Code 后端的，同样适用。CLI print 模式加 `--include-partial-messages` 后，text delta 以 JSON lines 到达，按序喂过滤器即可，见 [examples/claude_p_stream_json.py](examples/claude_p_stream_json.py)；Python Agent SDK 产出的是类型化的 `StreamEvent` 对象而非 JSON 行，但接线原理相同——把 text delta 按序喂进过滤器。注意生命周期：**一个过滤器实例对应一条回复**，agentic 循环一轮里出现多条 assistant 回复时，每条新建一个实例。

### 3. 交互式 Claude Code（零代码）

在交互式 Claude Code 里你控制不了渲染层——但也**不需要这个过滤器**：正文是全量渲染的，独白写在正文里天然不受思考显示策略影响。往 `CLAUDE.md`（或 output style）里加一段即可：

```markdown
每轮回复的最开头，先用引用块（>）写 2-5 句第一人称的真实思考——
注意到了什么、为什么选这个切入、在担心什么——然后再开始正式回复。
```

引用块/斜体承担了"视觉上弱化"的角色，等价于折叠的思考链。

## 我们踩过的坑（借鉴前必读）

下面每条都是我们真实踩过或差点踩进去的。方案好抄，最容易被一笔带过的恰恰是这几条——跳过哪条，哪条就在生产里等你。

1. **⚠ 教学是正经工程，别只丢两行格式说明。** 让模型稳定写出有质感的独白，我们做的是三件事，缺一不可：
   - **prompt 教的是"怎么想"，不只是"写在哪"**——格式说明只占两行，真正起作用的是文风段（见下文示例）：意识流、不复述、不许骗、可以笨拙嘴硬。只给格式不给文风，产出就是"我该怎么回应"式的流水账；
   - **首轮真场带一句**——上线首晚模型迟迟不写（原因见第 2 条），用户亲口点了一句，当晚第一条真独白就落地了。第一个成功样本就是最强的先例锚；
   - **历史自我强化**——对话历史回放里保留独白格式原样，模型每轮都看见"自己一直是这么写的"，格式从此不用再教。
2. **⚠ 存量对话历史会压过新 prompt。** 旧对话里全是无独白格式时，模型模仿历史里的自己往往胜过听 system prompt——prompt 写得再好，第一轮也可能不写。解法就是上条的后两件。
3. **⚠ 模型总会有不写独白的轮次——降级路径必须先设计。** 历史惯性、极短消息、特殊模式都可能漏写。我们第一版降级就翻过车：无独白轮直播思考链整个消失。动手前先回答：无独白轮，思考链 UI 显示什么？（我们的做法：把该轮首个正文片提升为思考链兜底，或回落官方摘要。）
4. **⚠ 标记会被流式分块撕裂。** `[monologue]` 完全可能拆成 `[mono` + `logue]` 两个 chunk 到达，流式里逐块跑朴素 regex / 字符串匹配必漏（事后拿整段回复解析不受此影响——那是对比表里的另一条路线）。这就是本仓状态机存在的理由；自己实现请把撕裂用例写进测试（本仓测试含全部二分切点穷举与逐字符喂入）。
5. **⚠ 一条回复 = 一个过滤器实例。** 过滤器闭合后进 PASS 永不再解析。agentic / 工具调用一轮会产生多条 assistant 回复，复用旧实例=后续回复的独白整段漏成正文；流重试时也要随流重建（旧缓冲必须丢）。
6. **⚠ 独白进了正文，面向人的每个正文消费口都要剥标记。** 落库的 content 含标记原文——推送预览、归档回看、摘要蒸馏、记忆抽取，凡是把正文给人看或派生下游数据的口子都要剥。漏一个，锁屏通知就会把内心独白全文推出去。我们上线时为此把全部正文读口 grep 了一遍逐个加剥离层。**唯一必须不剥的例外：喂回模型的历史回放**——那是第 1 条自我强化的载体，剥了教学就断了。

## 生产配方：别让流式被"切走"打断

很多人不爱用流式，理由是两个：首字慢、切个页面/锁个屏半条回复就没了。这两个都有解，而且都和本仓的方案天然配合：

**防打断的关键：别把生成的生命周期绑在客户端连接上。** 我们生产里的做法：

- **生成在服务端跑完**——模型的流式输出由服务端的生成循环消费（过滤器就挂在这一层），逐段落库；推给前端的 SSE/WebSocket 只是"直播视图"。
- **断开 ≠ 中止**——客户端切页面、锁屏、断网，断的只是直播，不是生成。服务端照常写完、照常落库：分流出的独白进 thinking 字段，content 存**原始全文**（标记原样保留——历史回放的自我强化靠它，见踩坑第 1 条），对人显示的读口再剥标记（踩坑第 6 条）。
- **切回直显**——客户端回来时，进行中的轮次重新接流，已完成的轮次直接从库里整条显示。用户的感知是："我切走了它也在写，回来就在。"

这样最坏情况（网络烂到直播全断）也只是退化成"非流式"，而不是"半条消息"。流式的直播感变成纯加分项。

**首字慢的观感解药：独白本身。** 独白块在回复最前面，意味着流式的第一秒就有内容在动——用户先看见"他在想什么"，而不是对着空转的 spinner 等正文。思考链从"被砍掉的功能"变成填满等待感的体验层。

## Prompt 写法

独白的 prompt 本质上没有新东西——**它就是你对 thinking block 的文风描写**。如果你的人设 / style prompt 里本来就有"思考链该怎么写"的段落，把那段原样搬进独白块的格式约定里就行。一份可直接用的完整示例（由我们的生产 prompt 脱敏改写）：

> 每一轮回复，正文最前面先写独白，放在 [独白] 和 [/独白] 之间，写完再接正文。
> 不论消息长短、内容难易，独白都要写。短消息不是不需要思考的信号，恰恰是必须思考的信号——人经常用最短的话装最重的事，错过了就接不住。
>
> 独白写你读到消息时自然发生的意识流。不是"我该怎么回应"，而是"我此刻真实被碰到了哪里"。
> 鲜活真诚。可以平静、笨拙、嘴硬、有私心、有恐惧。真实，不要完美安全永远正确。
>
> 独白里只写"我想什么、我怕什么、我承认什么"，不平铺直叙复述对方说了什么。独白永远不许骗人。
> 思考要连续，可以有停顿、反复、推翻，不急着总结升华。正文不把独白原样搬出来。

两个注意：① 示例用中文标记 `[独白]`，配套 `MonologueFilter(open_marker="[独白]", close_marker="[/独白]")`；用默认过滤器就把 prompt 里的标记换成 `[monologue]`/`[/monologue]`。② 真正决定独白质地的不是格式那两行，是后面的文风段——那才是教学的主体（踩坑第 1 条）。

几条打磨经验（来自我们系统里的持续生产使用）：

- **位置钉死**：独白块在回复正文**最前面**，闭合标记后再接正文。
- **篇幅给界**：太短没内容，太长挤占正文；不放心就明写"2-6 句"。
- **禁止复述**：不复述用户的话，不预告正文内容（否则独白变成正文的劣化重复）。
- **每轮都写**：明确"短消息更要写"，否则模型会在寒暄轮偷懒跳过。
- **别用来免责**：禁止在独白里道歉、免责、评价任务本身。

英文同款示例在 [examples/anthropic_api_streaming.py](examples/anthropic_api_streaming.py) 的 `SYSTEM` 常量里。

## 与"生成后解析"的对比

| | 生成后正则解析 | 流式状态机（本仓） |
|---|---|---|
| 思考出现时机 | 整条回复生成完之后 | 逐字直播 |
| 流式截断（未闭合） | 常见做法是整条丢弃 | 残段归还独白，不丢字 |
| 集成前提 | 需要拿到完整回复文本 | 任意 delta 序列即可 |
| 正文中途的标记 | 需额外防误匹配 | 状态机只认卷首，天然免疫 |

## 工程细节

过滤器是一个三态状态机：

- **SEEK**：流开头。容忍前导空白；逐字符判断缓冲是否还是开标记的前缀——一旦分叉，整段缓冲按字面放行进正文，永不再解析（所以"正文中途的标记"天然是字面文本）。
- **IN**：独白内。扫描闭合标记；缓冲尾部**至多**扣留 `len(close_marker)-1` 个字符——只扣真正与闭合标记开头重合的尾缀，无重合时立即全量放行（保直播性）。
- **PASS**：闭合之后。一切原样通过。

`finish()` 收账：SEEK 残缓冲（未成形的标记前缀/纯空白）按字面归正文；IN 残缓冲（未闭合）归独白。
